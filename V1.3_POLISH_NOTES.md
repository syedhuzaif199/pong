# Pong v1.3 Android polish patch

Implemented after initial Android device validation:

- Debounced settings autosave so Android settings persist without relying on graceful process shutdown.
- Android in-game MENU button using the existing pause/settings overlay.
- Android first-match control hint: hold upper/lower half to move the paddle; input remains -1/0/+1 for desktop parity.
- Touch-to-MENU region is excluded from paddle input.
- STUN DNS resolution and rendezvous create/join/wait HTTPS requests moved off the render/audio thread.
- Client rendering uses short RTT-aware ball extrapolation plus faster correction to reduce perceived latency without changing protocol 4 or host authority.
- Windows and POSIX Android link scripts statically link libc++ to avoid a missing libc++_shared.so at launch.
- Windows Android build keeps automatic installed NDK/CMake detection and the corrected raylib archive lookup.

Validation performed in the assistant environment:

- `go test ./...` in `server/`: passed.
- `bash -n build.sh build-release.sh android/build_android.sh`: passed.
- Source integration sanity checks: passed.

The assistant environment did not contain the project's pinned Odin compiler/Android SDK, so the modified Odin/Android client itself was not compiled there. Build and device validation should use the existing Windows Android setup that successfully built the previous v1.3 APK.


## r5 Android async fix

Android no longer instantiates Odin `core:thread` for rendezvous/STUN setup. Android Bionic deliberately omits POSIX thread-cancellation APIs (`pthread_setcancelstate`, `pthread_setcanceltype`) that Odin's current Unix thread backend references. DNS and rendezvous HTTPS now run on a Java worker owned by `NativeLoader`; the Odin game loop polls a small JNI result bridge. Desktop builds continue to use the Odin worker.

## r6 Android settings persistence

Android no longer relies on Odin `core:os` file I/O for preferences. The existing
`pong.cfg` text payload is stored in app-private Android `SharedPreferences` via JNI.
`commit()` is synchronous and autosave only advances its saved snapshot when the
commit succeeds. Logcat tag: `UDPPongPrefs`.
